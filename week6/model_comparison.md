# Model Comparison

All models trained and tested on the same 5-feature synthetic stock-prediction dataset (500 samples, 400 train / 100 test, stratified). Features standardized using training-set parameters only.

## Results

| Model | Variant | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|---|
| Majority-class baseline | — | 0.520 | — | — | — |
| Logistic Regression | raw features | **0.910** | 0.891 | 0.942 | 0.916 |
| Random Forest | 100 trees, raw | 0.900 | 0.889 | 0.923 | 0.906 |
| Gradient Boosting | raw features | 0.900 | 0.889 | 0.923 | 0.906 |
| Gradient Boosting | PCA (2 components) | 0.810 | 0.811 | 0.827 | 0.819 |
| Gradient Boosting | outlier-cleaned | **0.910** | 0.891 | 0.942 | 0.916 |

*Hyperparameters: GradientBoosting = `n_estimators=100, learning_rate=0.1, max_depth=3`. Random Forest = `n_estimators=100`. All `random_state=42`.*

## What each row proves

**Logistic Regression wins.** Data was generated by a linear rule on 3 of 5 features → a linear classifier matches the data-generating process exactly. Any nonlinear model is fighting the wrong battle.

**Random Forest and Gradient Boosting tie.** Both end up at 0.900. Bagging (parallel, errors cancel) and Boosting (sequential, errors corrected) converge here because there are no meaningful nonlinearities to exploit.

**PCA hurts.** -10 percentage points. PC1+PC2 only captured 43.1% of variance — projecting to 2D discarded 57% of the signal. This is the expected outcome when features are near-independent; PCA compresses *redundancy*, and there isn't any.

**Outlier cleaning helps Gradient Boosting.** +1 point (0.900 → 0.910), matching Logistic Regression. Isolation Forest flagged 20 rows (5%) as anomalies. Dropping them from training removed noise that was pulling tree splits in unhelpful directions.

## What this tells you about model choice

> Before reaching for XGBoost on every tabular problem: check whether a linear model already solves it. If the data-generating process is linear, boosting is expensive overfitting insurance that doesn't pay off.

Note: match the model to the structure of the problem, not the other way around.
